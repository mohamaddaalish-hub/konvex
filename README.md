# KONVEX | کانوکس — نسخه ۲

## Redesign سبز / Glass — فارسی و English

نسخه جدید روی همان پروژه، داده و منطق موجود ساخته شده است: تم روشن/تیره، header و footer شیشه‌ای، هویت سبز، حرکت آرام ذرات و نسخه کامل انگلیسی.

- فارسی: مسیرهای قبلی، مانند `/products`؛ انگلیسی: `/en/products`.
- تم و زبان در Header؛ توقف حرکت پس‌زمینه در Footer؛ reduced-motion سیستم رعایت می‌شود.
- پنل ترجمه محتوا: `/admin?tab=translations` یا `/en/admin?tab=translations`؛ ترجمه از داده فارسی جداست.
- PDF فارسی و انگلیسی از `npm run catalog:pdf` تولید می‌شوند.
- مرجع فعلی طراحی و معماری دو زبانه: **`docs/redesign/02-implementation.md`**.
- نتایج نسخه جدید و حدود آزمون: **`docs/redesign/03-quality-and-handoff.md`**.
- اطلاعات اصلی ۳۲ محصول، ۱۸ رکورد محتوایی و تنظیمات، با اثر انگشت قبل/بعد کنترل و حفظ شده‌اند. تست‌های نوشتنی روی دیتابیس جدا انجام شده‌اند.

**CSS:** فایل‌های `styles/` را ویرایش کنید. `app/globals.css` برای production تولید می‌شود و با `prebuild` به یک فایل ترکیب می‌شود؛ آن را دستی تغییر ندهید.

وب‌سایت اختصاصی فارسی و راست‌به‌چپ برای برند صنعتی کانوکس؛ کاتالوگ فنی، کشف محصول و درخواست استعلام B2B، همراه با پنل مدیریت مستقل.

**وضعیت این تحویل:** نسخهٔ اجرایی با داده و تصاویر نمونه. سبد خرید، پرداخت و ارسال اعلان واقعی جزو این انتشار نیستند. درخواست‌ها در پایگاه داده ذخیره می‌شوند و از پنل مدیریت قابل بررسی‌اند.

## مشاهده و مدیریت

در محیط Arena، پیش‌نمایش زندهٔ «وب‌سایت کانوکس» را باز کنید. برای فرم‌ها و پنل مدیریت، به‌ویژه در مرورگرهایی که کوکی شخص ثالث را مسدود می‌کنند، پیش‌نمایش را در **تب مستقل** باز کنید.

| بخش                | مسیر داخل سایت                           |
| ------------------ | ---------------------------------------- |
| صفحه اصلی          | `/`                                      |
| کاتالوگ و فیلترها  | `/products`                              |
| نمونه دسته تخصصی   | `/products/laser-distance-meters`        |
| نمونه صفحه محصول   | `/product/konvex-lm-60`                  |
| مقایسه             | `/compare`                               |
| استعلام محصول      | `/quote?product=laser-distance-meters-1` |
| کشف بر اساس کاربرد | `/applications`                          |
| دانشنامه           | `/knowledge`                             |
| مدیریت             | `/admin`                                 |
| کاتالوگ PDF نمونه  | `/downloads/konvex-catalog-sample.pdf`   |

اطلاعات ورود این محیط فقط در فایل خصوصی **`private/admin-access.txt`** قرار دارد؛ در کد صفحات، فایل‌های عمومی و آرشیو تحویل قرار نگرفته است. در نصب جدید، فرمان راه‌اندازی زیر رمز جدید می‌سازد.

## امکانات پیاده‌شده

- هویت بصری صنعتی اختصاصی، فونت محلی Vazirmatn، چیدمان RTL و مقادیر فنی LTR.
- ۳۲ محصول نمونه، پنج خانواده اصلی و یک گروه متعلقات؛ شش کاربرد و پنج راهنمای انتخاب.
- مگامنو، جستجوی نام/مدل/SKU/برند/مشخصات، پیشنهاد محصول و دسته، سابقه جستجو و میان‌بر `Ctrl/⌘ K`.
- فیلترهای مختص هر خانواده با شمارش واقعی، ترکیب AND/OR، مرتب‌سازی، صفحه‌بندی و نگهداری وضعیت در URL؛ پنل فیلتر موبایل.
- صفحه محصول با گالری، بزرگ‌نمایی، جدول فنی، کاربرد و سازگاری، اقلام همراه، FAQ، اسناد و پیشنهادهای مرتبط. وضعیت بدون دیدگاه، بدون امتیازسازی.
- مقایسه حداکثر سه محصول هم‌دسته، نمایش فقط تفاوت‌ها، استعلام گروهی، علاقه‌مندی و اخیراً دیده‌شده.
- فرم استعلام چندمحصولی با تعداد، راه تماس ترجیحی، اعتبارسنجی، رضایت حریم خصوصی، کد پیگیری و جلوگیری از ثبت تکراری.
- پنل رمزدار برای محصولات، مشخصات و تصاویر، گروه‌ها و فیلترها، برندها، مقاله‌ها، تنظیمات تماس و صندوق درخواست‌ها.
- گروه والد/فرزند، شمارش و جستجو در زیرگروه‌ها، جلوگیری از چرخه و حذف وابستگی‌های فعال؛ همگام‌سازی تغییر نام برند و پاک‌سازی روابط محصول حذف‌شده.
- SEO فنی شامل عنوان و توضیح مستقل، canonical، داده‌های ساختاری Product/Breadcrumb/Article، sitemap و robots پویا، پاسخ واقعی 404.
- ثبت رویدادهای تحلیلی از طریق `dataLayer` و رویداد DOM، بدون سرویس ثالث یا ارسال اطلاعات شخصی فرم به تحلیل‌گر.

## اجرای تازه روی سیستم خودتان

پیشنهاد استقرار: **Node.js 22 LTS یا 24 LTS**، دیسک پایدار و یک پردازش Node. وابستگی‌های بومی SQLite و Sharp برای سیستم مقصد باید نصب شوند.

```bash
npm ci
node scripts/setup-admin.mjs
npm run db:seed
npm run dev
```

پیش از اجرای `setup-admin.mjs`، فایل خالی `.env.local` نسازید؛ اسکریپت عمداً فایل موجود را بازنویسی نمی‌کند. رمز و secret تولیدشده را امن نگه دارید.

برای نسخه بهینه:

```bash
npm run build
npm run start
```

سرور به `0.0.0.0` متصل می‌شود. برای پورت دلخواه: `npm run start -- --port 3000`.

## داده و جایگزینی محتوا

- مدل‌های TypeScript: `lib/types.ts`؛ اعتبارسنجی: `lib/validation.ts`.
- داده اولیه مستقل: `data/seed.ts`؛ تغییر seed فقط **نصب تازه** را تغییر می‌دهد، نه دیتابیس موجود.
- داده زنده: `data/konvex.sqlite`؛ رسانه‌های بارگذاری‌شده: `data/uploads/`.
- ویرایش کاتالوگ موجود از `/admin` انجام می‌شود و به تغییر کد صفحات نیاز ندارد.
- تصویرهای اختصاصی تولیدشده در `assets-source/` و نسخه‌های WebP در `public/images/` قرار دارند. برای جایگزینی عادی، از بارگذاری پنل استفاده کنید؛ نام یکتای فایل از کش قدیمی جلوگیری می‌کند.
- برای بازتولید نسخه‌های responsive منابع: `npm run images:optimize`، سپس build مجدد. مجوز فونت در `public/fonts/OFL.txt` است.
- برای بازسازی شاخص جستجوی نصب موجود: `npm run db:reindex`.
- دسته‌ها و برندها شناسه مستقل از slug دارند. پس از انتشار عمومی، تغییر slug باید همراه با ریدایرکت 301 در لایه استقرار باشد؛ ریدایرکت خودکار تاریخچه slug پیاده نشده است.

راهنمای عملی مدیریت: **`docs/03-content-and-admin.md`**.

## آزمون و گزارش‌ها

```bash
npm run typecheck
npm run build
# سرور نسخهٔ production را در ترمینال جداگانه اجرا کنید.
npm run start

# فقط دیتابیس نمونه و قابل دورریختن؛ هرگز روی سایت عملیاتی اجرا نکنید.
ALLOW_QA_MUTATIONS=1 npm run test:e2e
ALLOW_QA_MUTATIONS=1 npx tsx scripts/clean-qa.ts
npm run qa:smoke
node scripts/quality-review.mjs
npm run qa:lighthouse
npm run test:scale
```

برای نخستین اجرای مرورگر آزمون: `npx playwright install --with-deps chromium`. آدرس آزمون را می‌توان با `TEST_BASE_URL` تغییر داد. برای دیتابیس آزمون جدا، **هم سرور و هم تست‌ها** را با `DATABASE_PATH` یکسان و مستقل اجرا کنید.

تست‌های E2E عمداً محصول و مقاله آزمایشی می‌سازند، تنظیمات تماس را موقتاً تغییر می‌دهند و درخواست نمونه ثبت می‌کنند؛ تأیید صریح `ALLOW_QA_MUTATIONS=1` لازم است. traceهای احتمالی می‌توانند حاوی اطلاعات ورود آزمون باشند و نباید منتشر شوند.

نتایج قابل بازبینی در **`docs/04-quality-report.md`** و فایل‌های `docs/qa/` قرار دارند. امتیاز Lighthouse آزمایشگاهی است، نه تضمین سرعت در همه شبکه‌ها یا گواهی جامع دسترس‌پذیری. INP و سایر داده‌های میدانی پس از استقرار و دریافت ترافیک واقعی باید اندازه‌گیری شوند.

## PDF و پشتیبان‌گیری

با سرور روشن:

```bash
npm run catalog:pdf
npm run db:backup
```

PDF هفت‌صفحه‌ای فعلی در `public/downloads/konvex-catalog-sample.pdf` است؛ قالب چاپ، هر خانواده را در بسته‌های شش‌محصولی صفحه‌بندی می‌کند. پس از تغییر محتوا، PDF ثابت باید دوباره تولید شود. این فایل و برگه HTML محصول، **سند رسمی سازنده نیستند**.

پشتیبان‌گیری از API خود SQLite استفاده می‌کند تا داده‌های WAL جا نمانند. نسخه‌ها در `backups/` با دسترسی محدود ذخیره می‌شوند. رسانه‌های `data/uploads/` را نیز جداگانه پشتیبان بگیرید؛ رمزگذاری و نگهداری خارج از سرور را برای محیط واقعی تنظیم کنید.

## پیش از انتشار عمومی

1. مشخصات، قیمت/موجودی، سازگاری و اسناد محصولات را با اطلاعات رسمی جایگزین و تأیید کنید. عکس‌ها و نشانه‌نوشتاری فعلی، نسخه اولیه‌اند.
2. تلفن، واتس‌اپ، ایمیل، نشانی، ساعات کاری و لینک نقشه واقعی را در پنل وارد کنید. هیچ شماره یا نشانی ساختگی فعال نشده است.
3. متن حقوقی، سیاست نگهداری درخواست‌ها و فرایند پاسخ‌گویی را با مسئول کسب‌وکار تأیید کنید.
4. رمز مدیر و `SESSION_SECRET` را عوض کنید؛ HTTPS، دیسک پایدار، بکاپ، پایش و دسترسی مدیر را تنظیم کنید.
5. `SITE_URL` را روی دامنه واقعی بگذارید. تنها پس از آماده شدن محتوا، `SITE_INDEXABLE=true` و پس از پایان نمونه‌سازی، حالت نمونه پنل را خاموش کنید. سرویس را مجدداً راه‌اندازی کنید.
6. سرویس اعلان ایمیل/پیامک یا CRM را در صورت نیاز متصل کنید؛ در وضعیت فعلی پیگیری از صندوق پنل **دستی** است.
7. سنجش سرعت، Safari/Firefox، دستگاه واقعی، صفحه‌خوان و بررسی امنیتی محیط نهایی را انجام دهید.

راهنمای استقرار و امنیت: **`docs/05-deployment-and-security.md`**.

## مرز این انتشار

- پرداخت، سبد خرید، سفارش، مالیات/حمل، حساب مشتری و اتصال انبار/ERP پیاده نشده‌اند؛ ساختار محصول و لایه داده برای افزودن آن‌ها تفکیک شده است.
- مدیر واحد است؛ نقش‌های سازمانی، MFA/SSO، تاریخچه کامل تغییرات و مدیریت چندمستأجره نیازمند توسعه‌اند.
- انتخاب‌های مرورگر snapshot محلی‌اند، نه موجودی زنده. قیمت و موجودی باید در فرایند استعلام تأیید شوند.
- مدیریت کاربردها و متن‌های ثابت هویت/صفحه اصلی فعلاً از داده و کامپوننت‌های مشخص انجام می‌شود، نه یک صفحه‌ساز عمومی.
- بارگذاری پنل برای تصویر است؛ PDF/ویدئوی واقعی باید در مسیر مجاز رسانه قرار گیرد و سپس به داده محصول متصل شود. بارگذاری مستقیم اسناد/ویدئو، درگاه رسانه و تعدیل دیدگاه عمومی جزو این نسخه نیستند.
- SQLite به دیسک پایدار و یک استقرار کنترل‌شده نیاز دارد. اجرای فعلی برای فایل‌سیستم موقت serverless یا چند replica آماده نیست؛ برای آن‌ها باید لایه داده/فایل/محدودسازی درخواست تغییر کند.
- وابستگی‌های runtime در audit ثبت‌شده مورد گزارش‌شده‌ای نداشتند؛ ابزارهای توسعه ۲۰ هشدار داشته‌اند. جزئیات و محدودیت‌ها در گزارش امنیت آمده‌اند.
