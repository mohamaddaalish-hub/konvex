# Konvex — راهنمای Redesign نسخه ۲

## محدوده و حفظ پروژه

این نسخه بازنویسی از صفر نیست. منطق repository، اعتبارسنجی، جستجو و فیلتر، مقایسه، استعلام، APIها، پنل و اسناد موجود حفظ شده‌اند. قبل از تغییر، SQLite و سورس پشتیبان‌گیری و اثر انگشت تمام ۳۲ محصول، ۱۸ رکورد دسته/برند/کاربرد/مقاله و تنظیمات ثبت شد. نتیجه مقایسه در `qa/data-preservation.json` است.

تست‌های دارای عملیات نوشتن فقط روی `data/redesign-qa.sqlite` اجرا شده‌اند، نه دیتابیس اصلی. نسخه اصلی `data/konvex.sqlite` برای پیش‌نمایش نهایی استفاده می‌شود. اعتبارنامه مدیر تغییر نکرده است.

## مسیرها و زبان

| بخش         | فارسی، بدون تغییر مسیر            | انگلیسی                              |
| ----------- | --------------------------------- | ------------------------------------ |
| خانه        | `/`                               | `/en`                                |
| محصولات     | `/products`                       | `/en/products`                       |
| دسته        | `/products/laser-distance-meters` | `/en/products/laser-distance-meters` |
| محصول       | `/product/konvex-lm-60`           | `/en/product/konvex-lm-60`           |
| استعلام     | `/quote`                          | `/en/quote`                          |
| مقایسه      | `/compare`                        | `/en/compare`                        |
| دانشنامه    | `/knowledge`                      | `/en/knowledge`                      |
| مدیریت      | `/admin`                          | `/en/admin`                          |
| ترجمه محتوا | `/admin?tab=translations`         | `/en/admin?tab=translations`         |

همه مسیرهای دیگر نیز همین الگو را دارند. `proxy.ts` و `i18n/routing.ts` با next-intl مسیرها را مدیریت می‌کنند. prefix زبان فارسی در URL لازم نیست. تشخیص خودکار زبان از cookie غیرفعال است تا مسیر قدیمی فارسی ناخواسته به انگلیسی منتقل نشود.

API و رسانه **پیشوند زبان نمی‌گیرند**: `/api/...` و `/uploads/...` ثابت مانده‌اند. درخواست‌های UI از URL نسبی استفاده می‌کنند. header اختیاری `x-konvex-locale: en` پیام‌های API را انگلیسی می‌کند. فیلدهای داده و شناسه‌ها همچنان canonical هستند؛ نتایج پویا فقط یک دیکشنری نمایشی محدود اضافه دریافت می‌کنند.

Language switcher پارامترهای جستجو/فیلتر و hash را حفظ می‌کند و با ناوبری client-side کار می‌کند. مقدارهای فرم استعلام، تعداد، روش تماس و رسید هنگام تغییر زبان در حافظه موقت همان صفحه منتقل می‌شوند؛ PII برای این انتقال در localStorage نوشته نمی‌شود.

## ترجمه محتوا

- متن رابط: `i18n/ui-en.json`؛ کلید نویسی و interpolation: `i18n/core.ts`.
- ترجمه اولیه تمام ۳۲ محصول و ۱۸ محتوای مرتبط: `data/translations/en-content.json`.
- داده انگلیسی زنده: جدول افزودهٔ `content_translations`؛ فارسی در جداول اصلی باقی می‌ماند.
- پنل «ترجمه‌ها» نام/مدل، وضعیت تکمیل، متن منبع و فیلد انگلیسی را نمایش می‌دهد. ذخیره ترجمه، دادهٔ فارسی، SKU، قیمت یا عدد فنی را عوض نمی‌کند.
- فیلترها از مقدار canonical استفاده می‌کنند و فقط برچسب نمایش ترجمه می‌شود؛ بنابراین تغییر زبان نتیجه فیلتر را تغییر نمی‌دهد.
- FTS هر دو زبان را در کنار مدل/SKU ایندکس می‌کند. ثبت ترجمه محصول، شاخص همان محصول را به‌روز می‌کند.
- Source editor قدیمی، دادهٔ فارسی را ویرایش می‌کند. در UI انگلیسی این موضوع صریحاً اعلام می‌شود؛ متن فارسی در فیلدِ مخصوص منبع، «UI ترجمه‌نشده» نیست.
- محتوای جدید یا منبع ویرایش‌شده به ترجمه/بازبینی نیاز دارد؛ ترجمه واقعی آن بدون دخالت صاحب محتوا اختراع نمی‌شود. پنل تغییر منبع را علامت می‌زند.

## ترجمه و مقیاس

همه ترجمه‌های ۵۰۰۰ محصول به مرورگر ارسال نمی‌شوند. `lib/dictionary-scope.ts` دیکشنری را برای همان مسیر و صفحه نتایج محدود می‌کند. `RuntimeTranslations` داده نمایشی همان صفحه را به client می‌رساند؛ نتایج جستجو و انتخاب‌های ذخیره‌شده دیکشنری موردنیاز خود را دریافت می‌کنند. cache حافظه مرورگر سقف دارد.

آزمون جداگانه ۵۰۰۰ محصول و ترجمه در `qa/scale-5000.json` ثبت شده است. این سنجش repository است، نه تست بار هم‌زمان زیرساخت عملیاتی.

## Design System

### منابع اصلی CSS

1. `styles/tokens.css` — رنگ، سطح، شیشه، سایه، radius، فونت و motion.
2. `styles/base.css` — layoutها، حالت‌ها و قراردادهای موجود.
3. `styles/design-system.css` — زبان بصری سبز/شیشه‌ای و سازگاری RTL/LTR.
4. `components/admin/admin.css` و `app/[locale]/print/print.css` — بخش مدیریت و چاپ.

در development فایل‌های modular به‌صورت import استفاده می‌شوند. پیش از build، `scripts/build-styles.mjs` آن‌ها را در یک stylesheet تولیدی ترکیب می‌کند تا درخواست‌های مسدودکننده کمتر شوند. **فایل تولیدی `app/globals.css` را دستی ویرایش نکنید**؛ منابع بالا مرجع‌اند.

### رنگ و شیشه

- Light: accent `#167451`، hover `#105D40`، متن `#14241C`، زمینه `#F2F5F3`.
- Dark: accent `#4CD49A`، hover `#6FE1B2`، متن `#EDF4EF`، زمینه زغالی `#101815`.
- متن روی CTA در روشن سفید و در تاریک سبز بسیار تیره است.
- Header، footer، dropdown، filter dialog و modal از blur محدود و border ظریف استفاده می‌کنند. کارت‌ها عمدتاً semi-glass‌اند و blur مستقل روی تک‌تک کارت‌ها ندارند.
- فونت فارسی Vazirmatn و انگلیسی Inter، هر دو محلی با subset رابط. فایل‌های اصلی و مجوزهای OFL حفظ شده‌اند.
- Logo همیشه LTR است؛ layout، sidebar، alignment، breadcrumb و جهت حرکت فلش‌ها با زبان تغییر می‌کنند. واحدها و مدل‌ها با bdi مستقل‌اند.

### Theme و motion

- تم قبل از paint تعیین می‌شود تا flash کاهش یابد؛ انتخاب کاربر در `kv-theme` ذخیره می‌شود و در نبود انتخاب از preference سیستم استفاده می‌شود.
- canvas تزئینی غیرتعاملی: حدود ۲۸ ذره/۱۸fps در موبایل و ۶۸ ذره/۲۴fps در دسکتاپ؛ DPR محدود است.
- scroll فقط ضریب سرعت را اندکی بالا می‌برد، حداکثر تقریباً ۱٫۲۴؛ موقعیت کل پس‌زمینه به scroll چسبانده نشده است.
- حرکت با مخفی شدن صفحه، حالت کاهش حرکت سیستم یا توقف کاربر متوقف می‌شود. کنترل توقف در footer وجود دارد.
- همه این حالت‌ها تست شده‌اند؛ این تست‌ها جای اندازه‌گیری توان مصرفی روی تمام گوشی‌های واقعی را نمی‌گیرند.

## تصاویر و اسناد

دادهٔ تصویر محصولات و فایل‌های اصلی حذف یا بازنویسی نشده‌اند. برای هماهنگی نمونه‌های تصویری با سبز برند، نسخه‌های مشتق جداگانه در `public/images/green/` ساخته شده‌اند. عکس‌های احتمالی بارگذاری‌شده کاربر دستکاری نمی‌شوند. تصویر hero، AVIF با fallback WebP دارد؛ تصاویر نمونه همچنان سند رسمی کالا نیستند.

- PDF فارسی: `/downloads/konvex-catalog-sample.pdf`
- PDF انگلیسی: `/downloads/konvex-catalog-sample-en.pdf`
- برگه فارسی محصول: `/api/products/:id/datasheet`
- برگه انگلیسی: همان مسیر با `?locale=en`
- بازتولید دو PDF با سرور روشن: `npm run catalog:pdf`.

## SEO

canonical و hreflang در هر زبان، sitemap دو زبانه و schemaهای محلی‌شده بررسی شده‌اند. headerهای alternate خودکار پراکسی غیرفعال‌اند تا با canonical دامنهٔ پیکربندی‌شده تعارض نداشته باشند. `SITE_URL` همچنان باید قبل از انتشار روی دامنه واقعی تنظیم شود. حالت noindex نمونه عمداً باقی مانده است.

## اجرا و آزمون

```bash
npm ci
# فقط اگر env هنوز وجود ندارد:
node scripts/setup-admin.mjs
npm run dev

npm run typecheck
npm run build
npm run start
```

برای آزمون نوشتنی، یک کپی مستقل SQLite بسازید و **هم سرور و هم تست** را با همان `DATABASE_PATH` اجرا کنید:

```bash
DATABASE_PATH=./data/redesign-qa.sqlite npm run start
DATABASE_PATH=./data/redesign-qa.sqlite ALLOW_QA_MUTATIONS=1 npm run test:e2e
npm run qa:matrix
npm run qa:mobile
npm run qa:performance
```

هرگز تست نوشتنی را روی دیتابیس عملیاتی اجرا نکنید. traceهای شکست ممکن است اعتبارنامه آزمون را در خود داشته باشند و نباید منتشر شوند.

## مرزهای باقی‌مانده

پرداخت، سرویس پیامک/ایمیل، CRM و MFA در این Redesign اضافه نشده‌اند و امکانات قبلی حذف نشده‌اند. اطلاعات برند و محصولات همچنان نمونه‌اند. تست موبایل شامل Chromium و WebKit شبیه‌سازی‌شده است؛ بررسی سخت‌افزار واقعی iPhone/Android و داده میدانی CWV، مرحله استقرار است. نتایج عددی و محدودیت‌های کارایی در گزارش نهایی آمده‌اند.
