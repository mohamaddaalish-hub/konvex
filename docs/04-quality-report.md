# گزارش کنترل کیفیت — KONVEX

تاریخ: **۶ سپتامبر ۲۰۲۶**. بررسی روی build بهینهٔ production در محیط محلی sandbox؛ Node.js 20.20.2، Next.js 16.3.4، Playwright 1.63 و Lighthouse 12.8.2. این گزارش ارزیابی همین نسخه نمونه است، نه تضمین محیط انتشار یا ممیزی مستقل امنیت/دسترس‌پذیری.

## خلاصه نتیجه

| بررسی                                           | نتیجه ثبت‌شده                                                               |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| TypeScript و production build                   | موفق                                                                        |
| E2E مرورگر/API                                  | 12 سناریو موفق؛ 0 شکست و 0 نادیده‌گرفته‌شده                                 |
| Smoke صفحات اصلی                                | 12 حالت دسکتاپ/موبایل؛ HTTP 200 و بدون overflow صفحه                        |
| بازبینی گسترده                                  | 78 حالت شامل موبایل/تبلت/دسکتاپ، پنل واردشده، تب‌های ویرایشگر و مسیرهای 404 |

عبور از axe به‌تنهایی گواهی WCAG نیست. تبلت در بازبینی گسترده از نظر layout/تصویر/اجرا بررسی شده؛ اسکن axe عمومی در دو عرض موبایل و دسکتاپ انجام شده است. جمع اسکن‌ها شامل حالت‌های تکراری و تعاملی است، نه ۷۸ صفحه مستقل.

## سناریوهای عملیاتی

۱. مگامنو و ورود به دسته از صفحه اصلی.
۲. جستجوی مدل، ارقام فارسی، واحدها، بدون نتیجه و انتخاب پیشنهاد با صفحه‌کلید.
۳. فیلتر اختصاصی، OR/AND، نگهداری URL، حذف فیلتر و صفحه‌بندی بدون تکرار نتایج.
۴. گالری/zoom، ذخیره پایدار، سقف سه مقایسه، رد دسته متفاوت، فقط تفاوت‌ها و استعلام گروهی.
۵. فرم خالی، خطاهای فارسی، ارقام فارسی تلفن، قطع شبکه، حفظ اطلاعات، تلاش دوباره و کد پیگیری.
۶. رد CSRF/Origin نامعتبر، دسترسی غیرمجاز و بازپخش امن یک استعلام با همان idempotency key.
۷. ورود پنل، ساخت/ویرایش/حذف محصول، بارگذاری و نمایش تصویر در production، تغییر وضعیت درخواست و خروج.
۸. منوی موبایل، فیلتر در پنل، CTA ثابت محصول و عرض‌های 360/390/768/1024/1440 در مسیر محصول.
۹. metadata، JSON-LD، سند HTML، PDF، sitemap/robots و 404 واقعی.
۱۰. CRUD گروه/برند/مقاله، زیرگروه، رد چرخه/فیلتر تکراری، وابستگی حذف، تغییر نام برند، sitemap زنده و خروجی HTML امن.
۱۱. ذخیره تنظیمات تماس و انعکاس در صفحه عمومی؛ بازگردانی داده اولیه بعد از آزمون.
۱۲. JSON معیوب/حجیم و جریان chunked، رد نوع فایل غیرمجاز، حفاظت upload و rate limit با 429/Retry-After.

فایل قابل بازاجرا: `tests/catalog.spec.ts` و `tests/admin-entities.spec.ts`. اصلاح‌های انتهایی شامل کنتراست حالت ویژگی خالی و یکنواختی تاریخ تهران بین SSR و مرورگر بود. آزمون E2E با timezone مرورگر Asia/Tehran نیز اجرا شد.

## سنجش Lighthouse

موبایل با پروفایل شبیه‌سازی/throttling پیش‌فرض Lighthouse؛ دسکتاپ 1440×1000 با پروفایل سبک‌تر دسکتاپ. اعداد جدول **آخرین اجرای ثبت‌شده** هستند، نه بهترین امتیاز انتخاب‌شده از اجراهای قبلی.

| صفحه / پروفایل            | Performance | Accessibility | Best Practices |    LCP |   CLS |    TBT |
| ------------------------- | ----------: | ------------: | -------------: | -----: | ----: | -----: |
| خانه — موبایل             |          91 |           100 |            100 | 3.38 s | 0.000 | 127 ms |
| خانه — دسکتاپ             |         100 |           100 |            100 | 0.72 s | 0.000 |   0 ms |
| متر لیزری / دسته — موبایل |          97 |           100 |            100 | 2.42 s | 0.000 |  94 ms |
| صفحه محصول — موبایل       |          90 |           100 |            100 | 2.95 s | 0.000 | 246 ms |

- هدف عددی Performance برابر ۹۰ و بالاتر در این چهار نمونه محقق شد؛ نتایج طبیعی میان اجراها نوسان دارند.
- **هدف LCP زیر ۲.۵ ثانیه هنوز در همه صفحات موبایل این سنجش محقق نشده است.** اولویت بهینه‌سازی پس از تأمین رسانه واقعی: کاهش CSS/JS غیرضروری هر مسیر، بازبینی اندازه/فرمت تصویر کلیدی و تنظیم CDN/کش زیرساخت، سپس سنجش دوباره.
- CLS در محدوده خوب است. TBT شاخص آزمایشگاهی است و جای INP را نمی‌گیرد.
- هیچ داده میدانی CrUX یا سنجش کاربران واقعی وجود ندارد؛ «قبولی قطعی Core Web Vitals» ادعا نمی‌شود.
- امتیاز SEO در این اجراها **۶۹** است؛ گزارش، مسدود بودن عمدی ایندکس با meta/robots را نشان می‌دهد. برای بالا بردن امتیاز آزمایش، محافظ ایندکس نمونه خاموش نشده است. پیش از ایندکس، دامنه و محتوای واقعی و سیاست‌های کسب‌وکار باید آماده باشند.

گزارش کامل هر اجرا: `docs/qa/lighthouse-*.html` و JSONهای متناظر. خلاصه ماشینی: `lighthouse-summary.json`.

## آزمون مقیاس ۵۰۰۰ محصول

دیتابیس آزمایشی **جداگانه** با ۵۰۰۰ محصول از خانواده‌های نمونه ساخته شد؛ دیتابیس سایت تغییر نکرد. هر query پس از warm-up بیست بار اجرا شد. زمان‌ها فقط repository/SQLite روی همین ماشین‌اند، نه تأخیر HTTP، عملکرد مرورگر یا آزمون هم‌زمانی.

| query                             |  میانگین |      p95 |
| --------------------------------- | -------: | -------: |
| First catalog page                |  8.72 ms |  9.26 ms |
| Laser category and all its facets |  9.31 ms |  9.59 ms |
| Technical model full-text search  |  3.42 ms |  3.52 ms |
| Combined technical facets         | 17.12 ms | 17.28 ms |
| Deep pagination                   | 55.46 ms | 56.99 ms |

فیلترها، FTS و pagination ایندکس دارند و تنها صفحه جاری به مرورگر داده می‌شود. این نتیجه مؤید ظرفیت داده نمونه است، نه تضمین بار هم‌زمان نامحدود؛ برای استقرار چندنمونه‌ای به پایگاه داده و فایل مشترک و rate limit توزیع‌شده نیاز است.

گزارش خام: `scale-5000.json`؛ بازاجرا: `npm run test:scale`.

## بازبینی بصری و محتوا

- خانه دسکتاپ/موبایل، دسته موبایل، محصول و استعلام، جدول مقایسه، CTA و نوار مقایسه هم‌زمان، پنل دسکتاپ و صفحات PDF بازبینی شدند.
- تصاویر lazy برای بررسی فایل خراب decode شدند؛ نبود تصویر در screenshot زودهنگام به‌جای شکست فایل گزارش نشده است.
- بخش فعال محصول هنگام پیمایش و قرار گرفتن جداگانه دو نوار ثابت موبایل بررسی شد.
- PDF دارای جلد و شش خانواده است؛ متن و تصویر با فونت محلی چاپ می‌شوند. تعداد SKU و سرریز صفحات کنترل شد.
- حالت بدون دیدگاه، بدون انتخاب، بدون نتیجه و اطلاعات تماس خالی، به‌جای محتوای ساختگی نمایش داده می‌شوند.
- رکوردهای مشخصِ آزمون پاک و تنظیمات تماس نمونه بازگردانی شدند. بکاپ SQLite نیز ساخته و خوانده شد.

## موارد باز برای انتشار

- عکس و مشخصات رسمی هر SKU، لوگوی رسمی، تماس/نشانی، اسناد و تأیید شرایط ضمانت و حقوقی.
- بهبود بیشتر LCP موبایل و اندازه‌گیری میدانی پس از انتشار؛ تست واقعی Safari/Firefox، iOS/Android و صفحه‌خوان.
- بررسی نهایی TLS/proxy، دسترسی مدیر، نگهداری/حذف PII، بکاپ خارج از سرور و مانیتورینگ.
- audit توسعه ۲۰ هشدار دارد: ۱۶ متوسط و ۴ بالا. `npm audit fix` غیرشکننده کافی نبود. ارتقای ابزارهای توسعه باید جداگانه ارزیابی شود؛ بسته‌های توسعه و traceهای حاوی اعتبارنامه روی runtime عمومی نصب/منتشر نشوند.
- پنل تک‌مدیر است؛ MFA/SSO/RBAC و audit trail کامل، اعلان/CRM، پرداخت و انبار زنده پیاده نشده‌اند.
- رتبه «پربازدید» داده نمونه/مدیریتی است، نه خروجی تحلیل واقعی بازدید؛ قبل از انتشار باید منبع معتبر متصل یا نام این مجموعه متناسب با گزینش مدیریتی تغییر کند.

نتایج خام در `docs/qa/` و راهنمای استقرار/مرزهای امنیت در `05-deployment-and-security.md` قرار دارند.
